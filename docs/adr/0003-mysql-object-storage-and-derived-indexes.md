# MySQL、对象存储与派生索引职责划分

> 历史记录：保留当时的决定、修订或验证证据，不表示当前运行状态，也不是执行授权。当前契约与操作入口见 [文档索引](../README.md)。旧文件名与版本仅为历史引用。

> **部分被取代**：ADR 0026 将 `business` / `dishes` 的 canonical OSS 当前分区定义为权威业务数据，MySQL 只保存当前分区目录；下文“清洗后的结构表是派生索引”的旧表述不再适用于这两个数据集。

企业资料中枢的权威元数据由 MySQL 等事务型数据库保存，包括员工账号、标签、资料目录记录、状态、对象存储位置、审计日志、处理任务、Skill 目录和经营事件元数据。原始文件和分析产物文件本体保存在 OSS 等对象存储中；向量表、清洗后的结构表和摘要索引都是可重建的派生索引，不作为权威资料库。

**Considered Options**: 直接以对象存储路径表达权限；把向量库当作权威资料来源。

**Consequences**: 所有文件访问必须回到资料目录记录和后端权限过滤；派生索引必须能追溯来源资料，并可随归档退出普通检索。
