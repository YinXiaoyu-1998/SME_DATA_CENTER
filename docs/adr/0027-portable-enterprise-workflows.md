# 可分发企业工作流由本机执行，SMEDC 管理业务配置

2026-11-01 至 2026-11-02 需求访谈已确认以下边界；尚未实现，不代表服务已发布、部署或租户已启用。现行操作仍以 [文档入口](../README.md) 为准。

最终实施规格为 [Issue #298](https://github.com/YinXiaoyu-1998/SME_DATA_CENTER/issues/298)，包含已确认需求及用户授权自行补齐的接口、迁移和测试设计；本 ADR 只保留边界及取舍。面向餐饮管理人员的 [图解使用指南](../guides/automation-user-guide.html) 是功能完成后的流程预览。

将数据采集入库、评价处理、自然周经营周报作为可分别安装的工作流，放入现有 companion skills 仓库，复用已有业务技能。基础 smedc-mcp Skill 负责介绍、引导和衔接安装；工作流业务执行由用户本机 Codex 承担。

SMEDC 保存有明确字段与校验规则的企业业务配置，由 MCP 提供当前授权内的配置读取；浏览器会话、邮件连接、凭据、本地目录和宿主定时任务留在本机。这样复用现有企业权限管理，同时保持 SMEDC 不充当 Skill 执行器的服务边界；企业配置不是任意脚本下发渠道。

配置归属为业务企业＋工作流，首版每个组合一份，可选择多个门店。组织是认证租户边界，不能以组织显示名自动替代业务企业。外部来源门店映射指向已有标准门店，不改授权身份或扩大范围。

首版每个业务企业的同一工作流由一台指定电脑负责，支持明确换机迁移，不做多机并行或自动接管。上传使用当前管理员身份，报告读取仍受独立业务权限约束。任务安装与对外动作授权分开；自动回复默认关闭，启用时明确门店白名单，邮件和其他动作同样由用户确认持续授权范围。

## 已确认的安装和运行边界

基础 SMEDC 安装完成后引导用户选择可选工作流。所选工作流检查企业配置、当前权限、美团登录与页面访问、下载能力及适用的邮件连接；缺项给出具体设置入口，可保留暂停任务，检查通过后启用。未登录美团不阻塞普通 SMEDC 使用。就绪检查区分就绪、待配置、待登录、权限不足和能力不支持。

每轮读取最新有效配置并固定业务参数版本；获取失败时停止受影响工作流，不静默沿用旧配置。暂停、撤销对外动作授权和移除执行电脑等控制在下一次外部动作前重新检查。保留配置版本用于解释运行范围。

Agent 可发现来源与标准门店并提出映射候选，由用户确认后保存。一个标准门店可以对应多个来源店铺，来源身份分别保留。未映射或歧义门店提示待配置，不能自动认定闭店；明确排除项才跳过，新增门店不自动扩大任何授权。

首版执行时间在本机 Codex 创建和管理，SMEDC 不另维护需要同步的调度时间；SMEDC 管业务配置、工作流启停和授权。故障仅停止受影响步骤，独立步骤继续；保留进度和结果状态，已成功的上传、回复、邮件不重放，未知结果先核对。

首版验收环境为 macOS、Codex 内置浏览器及 Gmail 连接。邮件是可选交付能力，未配置时仍可生成本地周报。业务工作流与宿主调度、邮件发送适配分离，预留其他邮件方式及具有定时任务能力的 agent；首版不宣称尚未验证的适配可用，也不硬编码本机路径或企业信息。

## 已确认的维护与迁移边界

轻量管理界面管理企业共用映射、三类任务设置、指定电脑与最近检查结果。准备检查与首次真实运行验证分开；准备检查不自动发送业务邮件或发布顾客回复。正常运行窗口保持前一日、前一天加当天、上个完整自然周；中断恢复原窗口，历史漏跑由用户明确授权补数。

仅有中央设置不足以保障换机不重复发送，因此 SMEDC 还保存最小安装登记、运行摘要、动作意图与确认回执；原件、报告和详细证据仍留本机，不成为云端任务执行服务。新机接管前处理旧机活跃轮和未知动作，撤销旧安装资格；已发出的第三方请求不能保证撤回。执行时间仍由宿主拥有，中央保存经确认的安装清单仅供换机重建，不形成第二套调度时钟。

麦家小馆现有三个任务及其引用配置和必要完成记录须一次性完整迁移。中央迁移完成后，新 Mac 只读复用企业设置，完成本机登录、检查和接管，无需重新填写 SMEDC 门店、邮箱、分组或回复规则；增删改仍走正常管理流程。未迁移或无法恢复的本地资料必须明确列出，不能假称无损恢复。

确认零结果与未成功取数分别记录，不凭零结果清空旧分区。普通运行不自行升级；明确更新须检查版本兼容并保留设置与完成记录。成功结果简洁呈现、需介入时通知；成功原件按各工作流资格精确清理，异常资料保留，最终周报默认保留。

## 已结账口径决策与兼容性依赖

2026-11-02 已确认首版自动化采用“已结账完整营业日”：选定门店、营业日内全部已结账订单，不额外按来源或支付方式缩小范围。服务应保存并向消费端展示来源口径，已有全状态数据须明确处理切换，不能静默互相覆盖。全部订单 29 列兼容不作为本工作流首版交付前提；已结账正式契约支持是交付依赖。

来源事实：2026-11-01 页面对照确认，美团店内订单明细切换到“全部订单”后，结账时间列及字段设置选项消失，切回“已结账”后恢复。本轮没有重新导出 XLSX；此前下载技能的 2026-10-31 记录称全部订单原件为 29 列。

当前服务要求 30 个来源列，结账时间可为空但不能缺整列；上传参数没有来源集合声明，同店同营业日的新内容替换整个当前分区。Issue #298 已明确新增来源口径元数据、未知历史标记、异口径受控切换与零结果不清空规则；这些设计尚未改变现行导入接口或运行中的任务。
