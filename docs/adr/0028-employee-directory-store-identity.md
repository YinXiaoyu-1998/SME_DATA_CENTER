# 员工档案独立于账号，门店使用唯一正式名称

2026-11-10 已确认设计，尚未实现。本 ADR 记录最终设计边界，实施和验收以 [Issue #327](https://github.com/YinXiaoyu-1998/SME_DATA_CENTER/issues/327) 为准。

## 账号与员工模型切换

员工档案按业务企业管理，每人一个内部 UID，必填姓名和部门，归属一家门店或集团直属。登录、业务授权与审计归属于 SMEDC 用户账号，系统不保存档案与账号的对应关系。员工离职、返聘和调动只改变档案。

登录和授权模型统一改为 `UserAccount`，新档案使用 `Employee`。HTTP、MCP 和浏览器契约中原先表示账号的 `employeeId` 等字段与实际消费者同步硬切为 `userAccountId` 等账号字段。保留既有账号身份、凭据、会话关联、授权、业务归属和审计关联。新档案使用 `employeeUid`。

## 门店身份与导入

复用现有 `business_stores`，为门店增加稳定 UUID，员工归属及新目录接口引用 UUID。同一业务企业内，每家门店只有一个正式名称，名称唯一。现存历史资料和授权所用名称键保持稳定，作为内部关联使用。正式改名在同一门店 UUID 上生效，新导入只接受更新后的正式名称，原名称不继续作为别名。来源平台商户号仅用于来源追溯和既有分区身份。正式改名须保留同一门店的现有分区身份，包括按名称生成的旧分区键，防止同一门店同一营业日形成平行分区。

上线时从既有登记生成待确认清单，由管理员按业务企业核对正式名单；管理员新建的门店直接确认。多个历史登记如疑似同一家店，只能选定一条作为正式记录，其余保留历史引用并退出日常选择与导入。管理员界面不提供关联门店、别名或历史归并操作。历史数据和授权需要纠正时单独核对并审批。

门店归属的新资料按组织、业务企业和正式名称精确校验。提交的门店名称与正式名称不同，或不存在可用于本次导入的登记时，退回本次提交，指出提交的名称、可定位的输入位置及处理办法。停用门店继续沿用既有停用和历史补录规则，历史补录仍须通过正式名称校验。不得模糊匹配、通过商户号放行名称差异、自动登记新店或改写来源文件。新店先由管理员登记，再导入。

评价工作流按 [ADR 0027](0027-portable-enterprise-workflows.md) 识别平台门店，在提交前把它映射为 SMEDC 的标准门店名。SMEDC 评价入库精确校验请求中的 `storeName`，平台展示名和 POI 用于工作流来源识别。本次门店目录改动的边界是 SMEDC 收到的门店归属，评价工作流的来源映射和现有配置沿用。

## 目录、员工权限与状态

- 门店和部门是按业务企业维护的基础目录。本组织的有效账号可按业务企业读取已确认且未停用的门店及未停用的部门，无需配置资料类别、密级或业务 grant。管理入口额外显示待确认与停用项。目录读取不包含员工名单、人数或来源明细。
- 员工档案使用独立读取类别和密级。门店员工按该门店范围授权，集团直属员工按集团级范围授权。名单、搜索、详情和计数只包含当前获准的范围。获准读取的离职档案仍显示保留的归属。
- 新增档案要求有效的本组织管理员身份和目标业务企业的管理资格，无需员工档案读取授权。没有对应读取资格时，成功仅返回操作结果和员工 UID。新增不产生读取授权。
- 编辑、调动、标记离职和恢复在职要求管理员资格与对现有档案的完整业务授权。改变归属时还须有目标归属的完整授权。UID 只标识档案，不能绕过授权。MCP、HTTP 和 Admin Console 使用同一套服务端规则。
- 默认只列在职员工。离职保留 UID 和原归属，返聘恢复原 UID。若原门店或部门已不可用，恢复时必须选择有效归属。保存时重新验证授权、目录和档案状态，避免并发变更使员工归属到不可用的门店或部门。
- 仍有在职员工归属的门店或部门不能停用。阻止信息不得暴露请求人无权读取的人员、人数或明细。停用门店与部门保留名称和标识；历史资料继续按原权限读取。

## 管理页面

- Admin Console 增设「企业资料」，包含「员工档案」「门店目录」「部门目录」。页首显示当前业务企业，多企业时提供切换。账号授权仍在权限管理中。原权限管理中的门店维护复用同一目录。
- 员工档案采用列表和按需打开的编辑面板。支持按姓名、门店、部门和在职状态筛选。列表展示姓名、归属、部门和状态，同名员工可用可复制的档案标识进一步区分。明确显示当前可见范围，分别提示无读取权限和筛选无结果。无读取权限的管理员仍可进入新增表单。
- 建档表单包含姓名、部门和明确的「门店／集团直属」选择，选门店时必须从有效门店中选择。调动保存前展示原归属和目标归属。名单刷新以服务端当前授权为准。
- 员工操作使用「标记离职」「恢复在职」。离职确认文案为「标记离职后，员工档案会保留，并从默认在职名单移除。SMEDC 登录账号和访问权限不会因此改变。」
- 门店目录分「正式门店」「待确认」「已停用」。待确认页用于核对既有登记，提供确认或保留历史记录的处理入口。部门目录显示名称和状态。沿用现有双语文案、表格、表单、状态标签和冲突处理方式。
