# 管理员权限设置 UI 设计

日期：2026-10-11。状态：用户已确认“固定入口＋管理员登录”和默认中文的国际化方向；本文及补充的企业专属入口／共享网页登录方案已获用户确认，页面已在本分支实现并完成本地验证，尚未部署上线。

## 目标与边界

开发者开通企业与管理员账号后，把官方权限设置页面的企业专属固定 URL 发给企业管理员。管理员本人在浏览器中选择、填写和维护本企业的权限，无需编辑 JSON，也无需为日常调整反复向开发者索取链接。页面地位与现有登录／密码设置页面相同：独立的任务页面，属于极简管理面。

一期覆盖已存在的权限模型与管理能力，不改企业隔离、密级、业务 grant、原件继承或切换语义。账号／组织创建、角色变更和密码重置仍由开发／运维负责；不增加员工自助注册、权限申请审批、资料正文浏览、报表或 dashboard。JSON 只作内部记录格式，不作为用户入驻要求，不增加整份 JSON 批量导入／导出功能。

## 入口与用户流程

- 企业专属固定入口为同源 `/admin/permissions/:orgId`，正式 URL 由开发者以现有非秘密组织 ID 填入 `https://api.smedatacenter.xyz/admin/permissions/<orgId>`。URL 不带密码、token、租户切换参数或自动赋权凭据，可以由开发者直接分享。
- 同一浏览器／用户配置在官方 Device Authorization 页面完成密码登录后，建立共享网页登录状态；30 分钟绝对有效期内打开本企业入口无需重复登录。Agent 凭据本身不等于浏览器会话，换浏览器、无痕窗口或会话过期需登录。未登录先进入管理员登录页，使用现有账号与密码；密码只在第一方浏览器页面输入。登录成功后回到原企业入口；服务端先验证 URL 组织与账号组织严格相等且当前为有效管理员，才显示配置。误把 A 链接发给 B：已登录 B 直接拒绝，未登录只可见通用登录页，登录后仍拒绝；不泄露 A 的存在、名称或配置，不自动改跳 B。每次页面与 API 请求均独立检查，不提供任意租户切换器。
- 开发者私下发的一次性密码设置链接和固定管理 URL 是两个入口。前者用于本人建立密码；后者可收藏并用于持续管理，不需要每次重新签发。企业专属固定 URL 本身不授予权限。
- 新企业首次使用按“类别密级 → 门店／业务条件 → 账号授权 → 检查与启用”引导。已有企业直接进入当前配置，新增账号复用企业规则，只补其授权。
- 页面明确显示当前模式：未启用（legacy／preparing）、已启用（enabled）、已暂停（suspended）。保存配置与首次启用是不同操作；不能将登录、填完表或保存成功表示为已切换。

## 页面范围

| 区域           | 管理员操作与约束                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 当前企业与账号 | 显示当前组织、管理员、授权状态；业务企业身份来自本组织已确认目录／资料关联，不用组织名称猜 business key                     |
| 固定类别密级   | 八类分别用下拉选择 0–3，空值显示“未配置”；保留固定 key、ownership 与既有 ID，不默认为 0 或 3                                |
| 门店与业务条件 | 维护精确门店目录、已有支持的维度及取值；显示停用项与历史含义，不做别名合并或自动更名迁移                                    |
| 账号授权       | 选择本组织已存在账号，显示其角色（只读），修改密级、类别、集团／门店范围与完整业务条件；管理员也需显式普通读取授权          |
| 普通文档       | 维护 evidence 类别及所需维度；按文档 ID／名称定位安全元数据，为整份文档修改类别、密级与完整范围，不返回正文、图片或下载链接 |
| 准备与启用     | 展示只读准备报告及具体缺项；ready 后展示本次切换影响，再由当前管理员单独确认启用                                            |

门店授权提供“无读取权限”“指定门店”“全部门店（包括以后新增）”；集团类别分别开关，不能用全部门店代替。额外维度采用完整组合条目，不把 A 店／X 项目与 B 店／Y 项目展开成四种授权。目录选项展示名称，内部绑定持久 ID，用户不填写 JSON、grant ID、组织 ID 或类别 ID。

普通文档使用逐文件密级与整件范围；结构化数据、照片和 PDF 使用类别密级。原始配送台账仍为内部生成材料：可设置其类别密级，但账号授权中没有开放原始明细、汇总或原件的选项。上传文件不属于本页面范围，继续走原有上传入口和官方 MCP。

业务企业选择来自本组织已配置的门店、grant 和资料范围中的精确身份。新空企业尚无业务身份时，由当前管理员明确填写业务企业名称，服务端沿用现有企业身份规范化规则返回 key，界面展示名称与规范身份供确认；确认后通过版本化事务和审计持久保存本组织的业务名称，刷新不丢失大小写；同一身份已有不同声明时拒绝覆盖，不自动更名或合并。确认后的身份用于相应门店／grant，不能自动从组织名或 URL 猜测。已有多个业务企业时逐项选择，授权明确绑定其中一个；不同历史名称不自动合并。此操作不创建或切换组织，也不把可见数据当成完整目录。

## 保存与冲突

以单个类别、单个账号、单份文档或单项目录为保存单位，保存前显示相应变更摘要。不同模块不伪装成一次全局原子保存；已经成功的修改与尚未保存的内容分开显示。

账号 grant 使用现有整套替换语义。UI 在当前快照上修改、保留未批准删除的 grant，对删除与撤权显示摘要，提交一次账号事务；不能因 UI 未展示某个停用类别或维度就顺手丢弃其既有授权。没有变更不发写请求。

每次写入携带最新 `expectedVersion`。版本冲突时保留当前页面内草稿并提示重载、比较和重新确认；不静默覆盖、不自动合并或盲目重试。默认不把权限草稿和目录存入 localStorage；退出或会话失效后不让未验证草稿自动提交。

缺少目录、密级、资料属性或来源关系时，显示具体缺项和下一步。UI 不猜归属、不自动创建全量 grant、不执行真实数据回填。准备检查只读；真实补齐另走批准的专门流程。

## 浏览器身份与服务端边界

复用现有 LoginIdentity／Employee 与密码校验、失败限制和认证审计；新增独立于 launcher 的共享浏览器身份会话，不把 launcher 的 access token 或 durable credential 交给页面，也不扩大原 `/v1`／MCP 接口的认证方式。

- 浏览器会话采用随机不透明 secret，服务端只存 hash，绑定身份、账号、组织与失效时间；官方设备网页登录成功和管理员页面登录成功都签发此会话，权限页面复用它；绝对有效期 30 分钟，不提供持久“记住我”或后台静默续期。到期重新登录。
- 会话 cookie 使用 `__Host-` 前缀、Secure、HttpOnly、SameSite=Lax、Path=/；登录成功更换会话，退出撤销当前浏览器会话，不顺带退出其他 launcher。
- 每次管理请求重新检查会话有效、账号有效、当前 admin 角色与 URL 组织严格一致。账号停用、角色降级或密码重置后旧会话不能继续管理；密码重置／身份会话撤销同时使相关浏览器会话失效。
- 管理浏览器请求走独立同源路由，验证 cookie；写操作同时验证 CSRF token 和 Origin。不得在 URL、页面脚本、Web Storage、错误、日志或 PR 中暴露会话 secret、密码或一次性设置链接。
- HTML 与配置响应 `no-store`；复用现有页面的 nonce CSP、禁止嵌入等头，按需允许同源请求；权限页使用 same-origin referrer 策略，使同源原生表单保留可校验 Origin，站外仍不发送 referrer。不加载外部脚本或 CDN。
- 当前有效 admin 可以管理本组织账号权限，即使其没有对应正文读取权；管理响应仍不能包含正文、行数据、原件或签名下载链接。

| 浏览器路由                                 | 职责                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------- |
| `GET /admin/permissions/:orgId`            | 固定管理入口；未登录转入登录，已登录渲染页面                                    |
| `GET/POST /admin/permissions/:orgId/login` | 同源管理员登录表单与校验，只有固定本地回跳目标                                  |
| `POST /admin/permissions/:orgId/logout`    | CSRF 校验后撤销当前浏览器会话并清 cookie                                        |
| `/admin/permissions/:orgId/api/*`          | 校验共享浏览器会话、企业匹配与当前 admin 的同源数据／写入路由，调用现有权限服务 |

原 `/v1/admin/permissions/*` 和 MCP 保留 bearer 鉴权与现有工具契约。共享业务 service／repository 与审计，不在 UI 中重写另一套授权，也不以浏览器后端代理用户提供的任意 API 路径。

## 数据与交付结构

页面表现与双语文案归 `apps/admin-web`，由现有 API 服务同源承载并随 API 镜像交付，不引入独立前端服务器。服务端路由、浏览器会话及管理元数据适配归 `apps/api`；权限事务和持久身份继续归现有 domain/db 层。复用现有轻量 HTML／页面交互方式，不为这个入口引入完整 SPA 框架。

实现增加浏览器会话存储及认证撤销关联；迁移为增量，不修改现有租户模式或 grant。业务企业标识和文档管理元数据只读适配需明确组织范围：业务企业候选从本组织既有配置与权威来源关联只读汇集，新的名称走显式声明与既有规范化校验，不新增平行的租户选择器；历史映射不足时返回准备缺项。普通文档列表只给名称、状态和权限属性，支持 ID／名称筛选、稳定游标分页，每页最多 50。新增 UI 适配不得变成普通员工的未授权资料目录。

本实现不新增 MCP 工具或改动其合同，不发布新 launcher。浏览器身份会话和确认的业务名称分别使用增量 BrowserSession 与 BusinessEnterpriseIdentity 表，密码重置／身份撤销会同步撤销网页登录；MCP bearer 认证边界不变。

## 国际化与默认语言

- 与现有登录／密码页共用 `zh-CN`／`en` 语义和 `smedc-locale` 偏好。首次访问默认中文，不根据浏览器语言或 Accept-Language 自动改为英文；缺失、非法偏好或存储不可用都回退中文。
- 用户明确选择英文后记住合法偏好，在权限、登录、密码相关页面间保持一致。切换语言不丢表单值、不保存业务变更、不改变身份或权限，更新 `<html lang>`、页面标题和可访问性标签。
- 页面导航、按钮、固定类别名称、字段／占位／帮助文字、空状态、加载／保存状态、表单校验、权限不足、版本冲突、过期／退出、变更摘要、准备缺项和激活确认均双语。应用错误按稳定 code 映射双语文案，不直接展示英文 exception 或堆栈；未知错误有双语兜底和安全请求编号。
- 企业、员工、门店、自定义类别及维度名称是用户数据，保持原样；不能因语言切换翻译、归一化或更改这些持久身份。
- 默认 HTML 即为中文，英文初始隐藏；中文／English 切换可键盘操作。应用自有字段校验、确认弹窗使用当前语言，不依赖浏览器原生英文校验作为唯一提示。
- 页面文案集中管理并检查双语 key 完整，避免把中英文散落在事件处理代码。内部 JSON key、API code 与版本字段不做语言化。

## 启用与交付

新企业流程：运维核对组织／业务身份并开通管理员 → 本人完成密码设置 → 开发者发送固定 UI URL → 管理员登录并配置 → 只读准备检查 → 明确确认启用 → 最小业务读取验证。新空企业可先启用再上传真实数据；没有真实资料时仅报告配置就绪。

已有 enabled 企业新增账号：运维创建账号 → 管理员从同一入口为其授权 → 核对权限卡和批准的读取，不重新激活全企业。已有 legacy 企业先显示旧模式与切换缺项，保存新配置不会提前改变读取模式。suspended 仅显示暂停状态与恢复要求，不提供“恢复 legacy”或绕过准备的一键恢复。

入驻流程、AGENTS.md 与双归属 Skill 统一引导管理员使用此 UI。页面上线前必须明确标记“已实现／尚未部署”，不让 agent 编造可用入口；确需当前管理操作时仍用已发布的官方 MCP 工具和现有授权边界，不要求用户填 JSON。

## 验证与完成条件

实施阶段只增加覆盖实际风险的测试：

- 默认中文、已有英文偏好、非法偏好／存储失败回退、页面跳转保持语言；双语字段与错误完整，切换不丢输入。
- 未登录、非 admin、跨组织、过期会话、停用／降级、密码重置撤销、退出、CSRF／Origin 与不安全回跳均不可写入。
- 修改一个账号保留其他授权；完整门店／维度组合、集团与门店区分、全量未来门店提示；版本冲突不覆盖。
- 八类密级、普通文档属性、ready／缺项与单独激活；无正文／签链泄漏，UI 与 MCP 对同一配置采用相同授权结果。
- 用合成数据对首次配置和日常修改做最小浏览器验收；不扩大为全套官方人工验收，不修改真实租户规则。

实现范围包含产品 UI、增量浏览器会话迁移和验证；线上部署与真实租户激活另行授权。按用户确认的设计制定实现计划并完成 UI；本次不部署或启用真实租户。
