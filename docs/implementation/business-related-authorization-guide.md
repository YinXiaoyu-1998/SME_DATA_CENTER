# SMEDC 权限设计：按实际使用场景说明

更新：2026-10-13。本文说明当前最终业务权限规则；企业需按准备流程明确启用，部署不自动激活。

本文用场景解释现行权限契约。技术定义见 [权限设计](business-related-authorization-design.md)，企业启用见 [切换手册](business-authorization-cutover.md)。

当前技术定义以 [正式设计](business-related-authorization-design.md) 为准；[设计问答](business-related-authorization-review.md) 仅为历史审阅记录。

## 1. 上传资料和读取资料是两回事

只有当前有效的管理员可以上传文件。上传后，系统可以继续正常解析数据、建立搜索内容、生成相关资料。

能否读取资料，则看员工是否有对应的信息类别、业务范围和足够的密级。属于同一家企业、上传过这个文件，或拥有管理员身份，都不自动带来普通读取权限。停用账号不能继续读取。

**例子：** 管理员可以上传一份 A 店经营表，但如果没有给自己配置 A 店经营数据读取权限，就不能以普通读取方式查询或下载它。管理员可以明确给自己授权，随后再读取。

## 2. 信息类别要分清，门店权限不能代替类别权限

一期按以下方式区分资料：

| 资料                           | 按什么范围分配权限                                   |
| ------------------------------ | ---------------------------------------------------- |
| 经营数据                       | 按门店                                               |
| 菜品销售数据                   | 按门店，与菜品基础目录分开                           |
| 会员数据                       | 集团级，不按门店                                     |
| 菜品基础目录                   | 集团级                                               |
| 供应商名单                     | 集团级                                               |
| 检疫证明照片                   | 每张只属于一家门店，是独立类别                       |
| 台账 PDF                       | 每份只属于一家门店，是独立类别                       |
| 原始配送台账                   | 内部生成材料，不向员工提供原始明细、汇总或原文件下载 |
| 普通文档，如培训材料、财务报告 | 管理员选择文档类别，并声明整份文档的范围             |

**例子：** 小王能看 A 店菜品销售，不代表能看菜品基础目录，也不代表能看 A 店财务报告。它们是不同信息类别。

## 3. 集团级不是“所有门店”的另一种写法

集团级资料需要明确获得该类别的集团级权限。拥有全部门店的经营数据权限，不自动获得集团级会员数据或供应商名单。集团级始终只限本企业，不跨企业。

**例子：** 小李有集团级会员数据权限且密级足够，就可以查看本企业所有会员数据。会员在 B 店开卡、A 店储值，不影响小李读取。开卡门店和储值门店只是信息字段，可用于筛选。

反过来，小王只有 A 店经营数据权限，即使某会员在 A 店储值，也不会因此获得会员数据权限。

## 4. 业务范围够，还要密级够

账号有一个统一密级，使用 0–3 级。资料要求的密级不能高于账号密级。业务授权和密级必须同时满足。

结构化信息、检疫证明和台账 PDF 按类别统一设置密级，由本企业管理员维护，作用于该类别的新旧资料。普通文档则逐份设置密级。

**例子：** 小王有 A 店经营数据权限，但账号是 1 级，经营数据要求 2 级，他仍不能读取。将账号提高到 2 级之后才可以。反过来，即使账号是 3 级，没有 A 店经营数据授权也不能看。

**另一个例子：** 经营数据从 1 级改为 3 级后，旧月份的数据和相应原文件也按 3 级检查，不继续保留旧的 1 级读取条件。

## 5. 一个人可以有多项授权，但不能把条件拆开拼接

一个人可以被授予 A/B 店经营数据、C 店菜品销售、集团级会员数据等多项权限。同一类别也可以分几次授予不同范围。多个类别适用完全相同的范围和条件时，可以一起授予。

**例子：** 小王有“A 店经营数据”和“B 店菜品销售”两项授权，不能把它们拼成“B 店经营数据”。

有多个业务条件时，每个实际范围都要被一项完整授权覆盖。不同范围可以分别由不同授权覆盖。

**例子：** 只想授予“A 店的 X 项目”和“B 店的 Y 项目”，应分别授予这两个组合。一次选择“门店 A/B、项目 X/Y”表示四个组合都允许，包含 A/Y 和 B/X。

## 6. “这几家门店”和“全部门店，包括以后新增的”要区分

可以固定授权 A/B 店，也可以明确授权某一类别的全部门店，包括以后新增的门店。后者不会自动包含新信息类别、集团级资料或未来新增加的必需业务条件。

**例子：** 总部经理获得“全部门店的经营数据，包括以后新增门店”，新增 C 店后可直接读取 C 店经营数据。只被授予 A/B 店的区域经理不能自动读取 C 店。

## 7. 门店按名字精确对应，不猜相似名称

业务权限使用本企业内的门店名作为门店身份，不做相似度检查或自动别名合并。现有商户号可以保留，但不当作已经贯穿所有业务的统一门店 ID。

**例子：** “陆家嘴店”和“陆家嘴一店”按两个名称处理。授权前者不自动授权后者，也不会因为名字相似而暂停导入，请管理员判断是否相同。

更名不自动迁移旧名称对应的资料或授权。如果以后需要正式更名并迁移历史关系，要明确办理这件事，不能悄悄合并。

## 8. 结构化原文件自动跟随解析出的数据权限

这是结构化文件的统一规则：业务逻辑给成功解析出的数据确定了哪些读取限制，原文件就自动受到这些限制。范围、类别、密级等都包括在内。未识别内容随原文件，不单独定权，也不要求管理员另行声明原件范围。

这里说的是系统实际保留的原文件，不是新增原文件保存功能。经营/菜品销售目前导入后只保留标准化的门店/日期分区，来源 Excel 不保留；这些数据仍下载获准分区。下面的原件例子用于说明有原件时的权限规则。

**例子一：** Excel 只解析出 A 店经营数据，另一张表没有识别。满足 A 店经营数据全部读取条件的人，可以查询这些数据，也可以下载完整 Excel，包括没有识别的那张表。

**例子二：** Excel 分别解析出 A、B 店经营数据。下载整份 Excel 要同时满足 A、B 的读取条件。只有 A 店权限的人仍可以查询或导出 A 店数据，但不能下载整份 Excel。

**例子三：** Excel 解析出集团级会员数据。原件跟随会员数据的集团级权限和类别密级，不额外要求储值门店或开卡门店权限。

系统要看这个文件解析出的全部数据，不能只看当前员工有权看到的部分来判断原件权限。原件也不另设一套上传时的旧密级；数据权限改变时，后续申请下载原件按当前规则检查。

## 9. 普通文档按整份管理，搜索段落跟着整份文档

普通文档走文档解析和搜索流程，管理员为每份文件选择一个业务类别、完整业务范围和文件密级。这个处理方式本身不是一个业务类别。

**例子：** 培训手册和第三方财务报告都可以上传为普通文档，但分别属于培训材料、财务报告，读取权限不会因为使用相同解析方式而混在一起。

**另一个例子：** 一份文档声明为 B/C 两店共有，即使搜索结果中的某段只提到 B 店，也必须同时满足 B、C 的完整读取要求才能看。需要分别开放时，应上传 B 店文档、C 店文档和 B/C 共有文档。

管理员可以在上传后更改整份文档的类别、范围或密级，整份文件和所有搜索段落一起跟随；不逐段另设权限。混合主题可设一个明确的组合类别或拆文件，类别名称、标签相似不会自动互授。

## 10. 检疫照片和台账 PDF 是两个可以分别授权的类别

每张检疫照片、每份台账 PDF 都只属于一家门店。照片、关联台账和 PDF 的门店要一致，不能只凭相同单号把别家店照片放进去。

**例子：** 小王只有“A 店台账 PDF”权限，可以看 PDF 中已经排好的照片和供应商信息；但不能因此单独下载检疫照片原件或浏览供应商名单。只有检疫照片权限，也不会自动获得 PDF 权限。

两类各有自己的类别密级。PDF 可以低于照片或供应商名单的密级，员工只需满足 PDF 自身的读取要求。

系统可以把集团级供应商名单中与单据准确对应、模板需要的地址和电话等信息放进门店 PDF，不把整个供应商名单带进去。以后增加其他来源或业务条件时，需要明确怎么正确使用，不能直接忽略条件。

## 11. 改照片权限与撤下照片，影响不同

只修改检疫照片的读取授权或密级，不改变旧 PDF 的权限，也不使 PDF 失效或重做。

**例子：** 检疫照片从 1 级升至 3 级，PDF 仍为 1 级。原本有资格看 PDF 的员工继续可以看。

照片内容被修正、替换、撤下或归档时，受影响的旧 PDF 失效，系统不再提供旧版下载。每日 PDF 巡检按最新有效照片自动重新生成；撤下的照片不放进去，替换的使用当前照片。新版成功就绪后可下载。

**例子：** A 店 PDF 放错照片，管理员撤下它。旧 PDF 不能再从系统申请下载；每日巡检重新生成不含该照片的新版，不必等管理员再上传一张照片才能触发巡检。若生成还有其他错误，则继续显示未就绪，不能拿失效旧版当成功结果。

供应商只是正常更新联系电话时，沿用不自动重做历史 PDF 的规则；下一次实际重新生成时使用当前目录。照片从 A 店改为 B 店则涉及实际来源不匹配，A 店旧 PDF 也要失效并按正确关联重做。

## 12. 查询可以只返回获准部分，整份下载不能偷偷少给

支持在线查询的类别，先限定在员工有权读取的数据里，再计算和返回结果。经营/菜品销售保持现有方式：下载获准的门店/日期分区，再由调用方进行分析，不新增服务端逐行查询或汇总功能。筛选条件不是新的授权。

**例子：** 小王只有 A 店权限，选择 A/B 两店经营数据时，系统只提供其有权读取的 A 店分区；后续统计也只能基于拿到的 A 店数据，并说明范围。

明确要求下载完整文件或打包指定清单时，不能把无权部分偷偷删掉，然后告诉员工完整下载成功。

**例子：** 员工明确选择 A、B 两店的指定文件打包，但没有 B 店权限。系统说明无法完成这份完整清单；员工可以重新选择只下载 A 店。错误可以说出缺少哪份资料的权限，不必含糊其辞。

原始配送台账的明细、汇总和原文件仍不向员工开放。员工可以查找台账 PDF、查看 PDF 准备状态并下载 PDF，不能借这些配套功能读取原始台账。

## 13. 权限修改立即影响之后的操作，已经拿到的链接保留原有效期

授权、账号密级、类别密级或资料权限修改后，员工之后的读取请求按当前规则检查，不必退出重新登录。

**例子：** 小王今天失去 B 店权限，之后不能再从系统申请下载含 B 店的原件。但昨天已经拿到的下载链接，仍按原有效期使用；原件链接如果原来有效 24 小时，就保留这 24 小时，不提前撤销。

翻页过程中，如果相关权限改变，系统要求重新查询，避免继续沿用旧结果。

## 14. 打包照常完成，领取下载链接时检查权限

提交打包时检查权限并固定资料清单。后台按清单制作，不实时监听权限变化，也不因为制作过程中员工的业务授权或密级变化而中断或标记失败。扩权不自动增加旧任务内容，撤权也不把旧任务缩成残缺文件。

**例子：** 小王有 A/B 权限时提交一个耗时五分钟的打包任务，第二分钟失去 B 权限。打包仍可完成，小王可以看到自己的任务已完成；但点击领取新的下载链接时，按当时权限检查，因为缺 B 权限而不提供链接。这不会把已完成任务改成失败。小王可以另建只含 A 店的包；若权限恢复且包仍有效，也可重新申请原包链接。

任务状态检查当前账号有效、同企业和本人身份，不把内容、文件下载或明细塞进状态结果。其他管理员可以看管理状态，不能接管他人的普通下载。文件缺失、来源失效、包过期等实际制作或有效性问题仍正常处理；已经拿到的链接继续按原有效期使用。

上传已经被系统正常受理后，上传者普通读取权限的改变，不会取消后台正常解析。上传处理和员工读取是不同操作。

## 15. 管理员是企业信任的权限管理者

管理员可以查看本企业所有账号的完整权限配置，包括自己、其他管理员和普通员工；也可以新增、修改、撤销这些账号的业务授权，调整其密级。管理员不必先拥有某项读取权限，才能查看配置或把它授给别人。查看别人的权限配置不等于直接读取别人能看的业务正文。

**例子：** 管理员目前只能读取 A 店资料，仍可为区域经理配置 B 店权限，也可明确给自己增加 B 店权限。这是其管理职责，不是自动拥有所有内容。

创建管理员时默认最高密级，但业务权限不隐式全开。开发者开户时可以显式配置初始业务授权；没有配置才为空。管理员之后可以降低自己的密级，仍保留管理权，并可再提高自己的密级。

账号创建、角色变更、密码管理仍由开发/运维负责，不因这次权限管理增加而全部交给管理员。既有账号角色变化不会自动改变业务授权和密级。

**例子：** 管理员被改为普通员工后，不能再管理权限，但其原有业务读取授权不会自动清空，需要按实际需要另外撤销。

## 16. 管理员能看处理状态，不等于能绕过正文权限

管理员可以查看维护和排错需要的账号、类别、门店目录、资料名称、权限设置、处理状态和安全的错误信息，即使自己没有正文读取权限。

**例子：** 管理员能看见“某财务报告解析失败”并处理问题，不代表可以直接下载报告或看到其中的财务明细。系统错误也不应把完整原始数据当作报错内容吐出来。

## 17. 员工可以看自己的权限，报错可以直说资料名称

员工可以实时查看自己的密级、获准类别和范围，以及“固定门店”还是“包括未来新增门店”等含义。即使密级不足，也可以知道自己被授了什么、还缺什么条件。

**例子：** 系统可以明确提示“你没有查看 A 店第三季度财务报告的权限”，也可以用名称、概述或说明原因所需的汇总信息解释，不要求把所有名字都藏起来。正文、业务明细和下载仍须按权限检查。

这不额外增加浏览全企业所有未授权资料目录的功能。员工需要更多权限时，可在产品外找管理员沟通，由管理员给予正常授权，不增加一次性绕过下载或内置审批流程。

## 18. 类别和业务条件可以扩展，但不能自动变成全员可看

管理员可以创建普通文档的业务类别，维护其适用条件和取值。结构化类别或新的结构化业务条件，需要开发明确数据怎么识别、怎么处理，再与管理员共同接入。两种资料使用同一业务条件时，共用明确含义。

**例子：** 管理员建立“培训材料”类别后，可以把已有支持格式的文档归到该类别；这不会自动让系统支持一种新的文件格式。也不能只新增“采购合同数据”这个名字，就让系统自动解析采购合同表格。

新增必需业务条件可以先准备、补齐资料和授权，再正式启用；启用后缺条件不能默认当成全部范围。

**例子：** 以后某类资料除门店外还必须按项目限制，就要补齐旧资料和员工授权对应的项目。不能因为旧授权没写项目，就默认允许所有项目。

## 19. 未准备好、关店、取消上传，各自怎么处理

新类别的密级和必需业务条件没有明确时，可以准备资料，但不把缺失条件猜成 0 级、最高级或集团级后开放读取。新导入失败，不替换既有且仍符合当前规则的有效数据。

**例子：** 新一批经营表处理失败，员工仍能读取原来有效的一批；但如果新的必需条件已经正式启用，旧数据也必须满足，不能借“旧数据”绕过。

门店或类别停用，不等于撤销历史访问。需要历史补录时，管理员可以明确办理并说明原因；停用不能恢复已经不支持的数据处理能力。有独立稳定标识的目录项不复用身份或硬删已有引用；门店更名按前面的名称规则处理。

**例子：** A 店关闭后，员工原有权限仍可用于查看 A 店历史经营数据；如果要禁止查看，应明确撤权或归档资料。

已发布资料的归档要求当前有效管理员。有效账号可以取消自己尚未完成的上传，只清理该未完成会话；不能以历史上传者身份撤销已受理处理或归档已发布资料。停用账号不能自助取消。

## 20. 管理操作留记录，旧数据切换时不能偷偷放宽

权限、密级、资料权限属性的修改，要记录谁改了谁、修改前后是什么。两位管理员同时改同一配置时，不能让过期页面悄悄覆盖另一人的修改。

通过企业专属最小权限 UI、官方 MCP 工具及对应管理接口提供管理和本人权限查看；账号密码等职责不因此扩大。权限检查由服务端统一执行，不能靠客户端自己隐藏按钮。

旧企业先准备新类别规则、资料属性和账号授权，由管理员明确确认，再切换。结构化原件按已解析数据自动确定权限，不额外人工补配一套原件范围；普通文档则按自己的整份声明规则处理。

**例子：** 从旧规则切换到新规则后，某员工缺 B 店授权，就不能因为旧规则曾允许而继续放行。如果系统故障回退，也必须保留新权限检查；做不到就暂停相关读取，不能自动恢复旧的宽松权限。切换保留原始资料，不擅自删除。

本文是使用说明，不构成执行部署、账号授权变更、真实资料迁移或回填的授权。
