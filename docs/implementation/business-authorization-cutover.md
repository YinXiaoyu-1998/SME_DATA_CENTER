# 企业业务授权准备、启用与安全暂停

本流程沿用账号的组织租户边界，资料的 `enterpriseKey` 约束继续生效。迁移只增加 schema 和配置能力，部署不会自动启用真实企业、产生 grant 或推断历史资料属性。真实企业补齐和切换需要另行授权。

1. 当前 admin 配置初始化写路径按开发登记清单幂等补齐固定类别，新企业由账号开通流程初始化；既有迁移不代表后续新类别已在真实企业完成配置。初始化保留已有类别身份、密级和停用状态，新类别密级保持未配置，不创建 grant、不启用企业。目录列表和准备检查均只读。当前同组织有效 admin 从类别列表取得实际 ID，再配置已接入可读取固定类别的企业密级。原始配送台账类别保留内部身份，不要求管理员设置密级；启用和入库仍校验其存在及完整企业／门店／来源关联，不推断或改写已有内部密级。缺失内部类别返回 `INTERNAL_CATEGORY_REQUIRED`，须完成服务初始化。配送台账 PDF 独立配置密级与授权。不得从历史上传密级、最高级或默认 0 推导。配置 evidence 类别/维度，逐份明确类别、密级和完整范围；照片明确唯一门店。精确门店目录、维度值及 grant 必须引用同一持久化身份。
2. 用 `GET /v1/admin/permissions/cutover` 取得只读准备报告。`authorizationVersion` 绑定当时的权限和发布状态；`missing` 列出类别、资料、成功解析原件关联、目录、grant 和读取适配器的缺项。`accountsWithoutGrants` 是信息项：空 grant 是合法的无业务读取权账号，准备不会自动授权。
3. 结构化原件沿用全部成功解析范围，不独立定权，不要求未识别部分也完整解析。缺少可证明的来源关联会阻止启用，须用专门的、另行授权的补齐流程处理；不能把当前可见行当成整件范围。分区和已发布 PDF 必须有对应完整要求。
4. 缺项补齐后重新准备。admin 明确确认时提交 `POST /v1/admin/permissions/cutover/activate`，正文仅有 `{ "expectedVersion": "准备报告版本", "confirm": true }`。事务在版本锁内复核当前 admin 和完整准备条件，成功才原子设为 `enabled` 并记审计。类别/grant/发布变动使旧版本返回 `AUTHORIZATION_VERSION_CONFLICT`；缺项返回 `AUTHORIZATION_CUTOVER_NOT_READY`，均不部分启用。

准备期明确使用旧模型；新请求在启用后仅使用新模型。请求的读取模式、规则和版本来自同一服务端快照，请求内复用，跨请求重载。切换使旧查询游标失效。原件/PDF 签发在返回能力前复核事务版本；分区签链在权威锁内复核整份清单。旧客户端仍由服务端新规则鉴权。

打包始终按提交时固定清单制作，单纯撤权不改变完成状态。领取新链接检查当前整份权限。可证明全部身份、内容和范围的旧清单继续适用；不能证明的旧任务提示 `PARTITION_DOWNLOAD_REBUILD_REQUIRED` 或 `LEDGER_DOWNLOAD_REBUILD_REQUIRED`，须重新准备。既有已签链接保留原 TTL；原件 TTL 仍为 24 小时。

新增必需维度也先准备、明确补齐资料和 grant、再确认启用；缺项始终拒绝，不能由旧原件、游标或客户端绕过。目录停用不会抹去历史身份或自动撤销历史访问；历史补录使用当前 admin 的明确理由和既有审计机制。

## 技术回退

回退保留新增 schema、资料关联和新授权，禁止反向迁移或恢复 `legacy`。如候选旧代码无法完整执行新授权，必须先暂停受影响读取：当前 admin 以当前版本调用 `POST /v1/admin/permissions/cutover/suspend`，正文同样仅有 `expectedVersion` 和 `confirm: true`。此操作只适用于已启用/暂停企业，原子设为 `suspended` 并增加版本/审计。暂停后资料读取和新链接拒绝，后台不能发布新资料；本人安全进度和 admin 配置管理按各自身份边界保留。

不得把不认识 `suspended` 的旧二进制接入员工流量；必要时在流量入口保持读取停服，直到部署支持新模型的版本。恢复读取须先部署兼容代码、重新验证完整准备条件，再按另行确认的恢复操作执行；启用接口不会把暂停自动改回旧授权。数据库和对象内容不反向变更。

本地合成回归覆盖只读准备、缺适配器、过期类别/grant/发布版本、当前 admin、事务前后快照、签链失效版本、暂停无旧读取出口和旧任务重建。全库门禁和部署后的同 fixture 验证在最终审查/部署授权边界执行；本流程不授权真实资料回填或官方人工全套验收。

## 店铺评价接入与真实切换边界

`store_reviews` 随固定类别初始化登记为门店级、密级 null、无默认 grant。prepare 清单核对已登记企业键、每条 `store_review` 与其唯一同 ID 资源、固定类别/企业/单门店属性，并登记 `store_review_query` 读取消费者。缺新类别影响新功能/切换准备，不改变已 enabled 租户旧类别的读取策略；不能靠普通查询自动配置类别或激活租户。
评价写入沿用授权发布锁和事务内当前有效 admin 检查，每批全成或全败；读取与企业候选采用实时快照及完整 grant。评价写入（包括 unchanged 批次）和权限变动都会使旧游标失效。使用已发布并独立验证的 launcher `0.12.0` 安装 pin，并另行核对匹配服务部署。本接入不授权真实权限变更、数据回填、远端迁移或 staging 部署。
