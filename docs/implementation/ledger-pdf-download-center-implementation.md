# 台账 PDF 下载中心实施计划

**权威规格：** [GitHub Issue #262：台账 PDF 下载中心与一周网页登录](https://github.com/YinXiaoyu-1998/SME_DATA_CENTER/issues/262)，标签 `ready-for-agent`。完整需求、40 项用户故事、实现边界及验收决定以该 Issue 为准；本文只保留执行拆分、复用位置和验证入口。

**设计参考：** [已确认的交互原型](ledger-pdf-download-center-design.html)。原型中的合成数据、计时器和演示按钮不进入生产代码。

**状态：** 规格已整理，生产功能尚未实现。实施以最新 `main` 为基线，使用 `codex/ledger-pdf-download-center` 功能分支；优先复用适合的工作树。遵守根 [AGENTS.md](../../AGENTS.md) 与 [Agent skills 配置](../agents/issue-tracker.md)，默认单 agent 顺序实施、批次自检、一次整体 review 和最终门禁，不逐私有函数或小任务扩张测试/PR 边界。

## 复用与必要改动

| 能力              | 复用位置                                                         | 必要改动                                                   |
| ----------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| 密码、身份与撤销  | API 的 `AuthCore`、`BrowserSessions`、现有浏览器会话持久化       | 一周期限、普通员工网页入口和同源身份适配；不新增身份模型   |
| Cookie 与网页安全 | 现有 Cookie、CSRF、Origin、审计及安全响应头                      | 共享身份 Cookie 允许 604800 秒；其余短期 Cookie 保留原限制 |
| 台账读取与大小    | 台账交付服务、当前账号/授权、`readFact`、来源和对象有效性检查    | 网页投影带出已有 `byteSize`；精确键读取复用原判断          |
| 单份 PDF          | 既有 PDF、`StorageAdapter.getObjectStream`、ZIP 命名规则         | 同源 inline/attachment 流式交付；不经过 ZIP 或重新生成     |
| 批量 ZIP          | `reserveBundle`、manifest entries、请求所有者、worker、租约/清理 | 接受精确清单并绑定幂等指纹；复用原任务与 manifest 格式     |
| 网页与发布        | `apps/admin-web`、API 页面注册/镜像、现有双语和发布方式          | 正式列表/选择/预览/状态交互；不新增前端服务或运行时依赖    |

限额从现有台账模块统一导出并注入网页，避免前后端各写一份：5000 份 PDF、50 家显式指定门店、366 个不同日期、连续查询范围 366 天、每批 200 项、原 PDF 合计 1 GiB。沿用现有 ZIP 超时、保留期与签链期限。

## 已确认的测试边界

- **主边界：现有 Fastify HTTP 接口。** 复用实际应用注册、会话和交付服务，以状态码、Cookie/响应头、JSON、PDF 流、任务状态与 ZIP 文件清单验证外部行为。参考既有管理员网页路由、设备登录和台账 HTTP 测试。
- 快速接口用例使用现有合成身份、权限、存储/仓储 fixture；不把整个待测服务 stub 成成功。只在必要的持久化链路使用现有临时 loopback MySQL 和本地存储集成路径。
- ZIP 的执行复用已有 worker 测试/任务执行入口，不开第二套队列或模拟后台。
- **浏览器补充验收：** 跨页/跨查询选择、大小反馈、等待/禁用范围、预览切换、今日未就绪而历史可用、会话恢复、中英文和移动端。复用既有页面脚本检查与浏览器能力，不新增通用 E2E 运行器。
- 测试绑定用户可见行为和公共入口，不规定必须拆出哪些私有辅助函数；1 GiB 等边界使用合成元数据，不制造大量大文件。

## 批次 1：共享网页登录一周

**主要位置：** `apps/api/src/auth/`、现有官方设备登录与管理员网页路由及其测试。

- [ ] 先通过现有登录 HTTP 入口增加回归：共享身份 Cookie 的 `Max-Age=604800`，七天前有效、恰好七天失效，访问不续期；密码重置、停用和退出仍能撤销。
- [ ] 调整共享会话期限及 Cookie 签发上限。`hostOnlyCookie` 当前最多允许 86400 秒，只对此身份 Cookie 放宽；其他短期 Cookie 不变。保留当前导出/调用兼容，旧已签发会话不追溯延长。
- [ ] 验证管理员页、设备网页登录与后续下载中心可复用同一浏览器会话；退出网页不撤销 MCP 会话，现有程序化接口不新增 Cookie 认证。
- [ ] 自检新用例与相关现有认证路由回归。本批次不做独立发布。

## 批次 2：受权列表、文件大小与单份 PDF 网页

**主要位置：** 新网页路由放在 `apps/api/src/ledger-web/` 并接入现有 server/context；页面放在 `apps/admin-web/src/`；台账能力扩展现有 `packages/ledger-archive` 交付模块。

- [ ] 先写网页 HTTP 行为用例：普通员工登录、无会话转登录、同组织授权列表、管理员无读取旁路、跨组织拒绝、四态/大小、200 项游标、inline/attachment PDF 及安全头。
- [ ] 使用 `/ledger-pdfs` 同源页面及其独立网页 API 命名空间，覆盖登录/退出、当前本人安全上下文、覆盖查询、单文件和后续 ZIP 交付；复用现有 Cookie/CSRF/Origin/审计代码。组织来自会话，不接受任意组织、对象键或 return URL。
- [ ] 网页覆盖响应为 ready 文件增加正整数 `byteSize`，其他状态为空；不修改既有 MCP 响应。支持按查询范围读取，以及对当前精确选择重新核验；仅投影允许公开的字段。
- [ ] 门店选项从已加载的受权覆盖结果提取，明确为“已加载门店”；沿用游标前后翻批，不承诺完整门店目录、全局 count/排序或任意页跳转。
- [ ] 单 PDF 经当前权限、来源和对象检查后，复用存储流交付；组织内门店原名/日期决定目标。安全命名复用现有 ZIP 规则，必要时提取一次共享函数；不要从 API 导入 worker 模块。
- [ ] HTML 保留既有安全头与双语机制，只为下载中心允许同源 PDF 嵌入；预览使用原生 viewer，始终提供单份下载。浏览器不支持内嵌查看时仍能下载，不增加 PDF 渲染服务。
- [ ] 从原型迁移正式布局与查询/预览反馈；用户名称通过安全文本/转义显示。验证今天 pending/stale 不影响历史 ready，无进货记录时不生成假行。
- [ ] 自检接口和必要浏览器路径；使用现有存储与合成 PDF，不请求真实企业资料。

## 批次 3：跨页清单、容量反馈与精确 ZIP

**主要位置：** 现有台账交付服务及仓储、ZIP worker 的共享限额/命名引用、新网页 API 和客户端状态。

- [ ] 先写 HTTP 关键用例：A 店/1 日 + B 店/2 日仅交付两份；一个目标不可读/未就绪则整批拒绝；清单重排幂等、改项冲突；1 GiB 与多一字节；5000/50/366 边界；未选候选组合很多时不错误触发限制。
- [ ] 在权限、来源和数量判断前按精确键限定读取，复用现有 `readFact`/批量元数据校验；不把选择扩成门店与日期的笛卡尔积。幂等指纹绑定当前组织、员工及规范化的完整清单。
- [ ] 复用现有 `reserveBundle`、manifest entries、ZIP 请求和 worker；领取 URL 时也按原捕获键检查，不能重新扩成范围。保持现有 JSON manifest 格式与旧 HTTP/MCP 语义。
- [ ] 前端在当前页面内存中维护跨批次、跨查询选择；本批全选仅选择本批可选项。“已选清单”显示全部所选并按大小优先，允许单项取消或清空。
- [ ] 用原 PDF 整数字节合计显示总量、余量与超出量；未知大小不作零。超限禁用提交并保留全部选择，取消文件后恢复；服务端依然最终校验，不自动返回删减后的包。
- [ ] 用真实请求状态代替演示计时器。重复创建请求复用幂等键；新清单/明确重新准备才创建新请求。打包期间锁定本次选择，弹窗关闭后仍可查询/预览并查看该任务。
- [ ] 按以下阶段规则回归，复用既有 ZIP worker 和完整性测试，不新增撤权监听/取消机制。

| 阶段     | 必须保留的行为                                                                             |
| -------- | ------------------------------------------------------------------------------------------ |
| 提交     | 当前完整权限与有效性检查，通过后固定全部目标及内容引用                                     |
| 制作     | 由内部任务按固定清单制作，单纯发起人权限变化不取消；来源失效、租约、超时和完整性检查仍适用 |
| 状态     | 当前有效本人可读安全状态，不附文件正文或下载链接                                           |
| 领链     | 当前仍能读取清单全部内容且包有效才发链接；不足则拒绝链接，不把成功任务改成失败             |
| 已发链接 | 按既有 TTL 使用，后续扩权不会向旧包增添文件                                                |

## 批次 4：恢复、兼容及统一交付检查

**主要位置：** 网页交互、现有本地集成运行器、相关现行文档和双归属核心 Skill 入驻说明。

- [ ] 验证查询/翻批局部加载、单文件独立等待、旧预览响应不覆盖新目标、ZIP 终态停止轮询、失败保留筛选/清单。页面只确认“下载已发起”，不虚构百分比或落盘完成。
- [ ] 会话过期时停止请求并保留原页内存选择；在独立登录页完成认证后，原页更新本人安全上下文/CSRF，再重新核验完整选择。身份变化后重新加载当前账号；未返回/未知项交由用户处理，禁止静默丢项。
- [ ] 历史文件与今日状态分别处理；每日任务是否开启不控制网页入口。既有服务错误按可重试错误显示，不伪装空列表；不新增运维开关 UI/状态接口。
- [ ] 复用现有本地集成运行器登记本功能关键路径及浏览器会话持久化用例，使用原有临时数据库/存储和清理流程；认证用例显式启用既有 `RUN_AUTH_INTEGRATION`，不新建运行器。
- [ ] 更新相关现行登录、管理员界面、台账和网页 API 文档。核心 Skill 入驻说明中的“30 分钟”须在服务仓库与 `YinXiaoyu-1998/smedc-mcp-skill` 相同分发目录同步；依现有约定单独分支/PR，纯指导修订不发布 launcher 或改安装 pin。
- [ ] 最终树执行一次项目门禁与相关集成/打包验证，完成一次整批 review；检查无计划外 schema、依赖、存储服务或其他功能扩张。
- [ ] 按现有授权推送功能分支、创建服务 PR 并协调必要的 Skill 文档 PR；说明 scope、验证、环境、人类输入、限制及分类增删行数。仅包含本功能及明确要求的设计/计划，保留其他工作独立。

## 验证入口与完成标准

开发阶段从相关 HTTP/会话用例开始，只运行证明本批变化的最小测试。最终树一次执行：

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
MYSQL_PORT=3307 npm run test:integration
npm run build:release
```

相关先例：管理员网页和台账 HTTP 路由测试、共享浏览器会话集成测试、台账受权交付与 ZIP worker 测试。完整官方人工验收和性能测量不在本计划默认范围。

完成意味着 Issue #262 的用户可见行为和关键拒绝路径均有证据，旧管理员页/程序化接口回归通过，实际页面没有演示数据/计时成功逻辑。PR 合并、正式部署、真实租户激活和回填仍是不同阶段；本计划不授权部署、调度修改或真实数据操作。
