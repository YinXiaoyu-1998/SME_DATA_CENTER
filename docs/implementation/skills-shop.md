# Skills Shop 已确认设计

状态：以下为最终确认的部分设计边界，技能包上传/托管功能尚未实现。当前运行服务只有 Skill 目录元数据读取；本文不提供可执行的上传/安装 API。当前领域入口为 [CONTEXT.md](../../CONTEXT.md)。

## 定位

Skills Shop 托管经维护者上传、审核的业务技能包，员工 agent 获取固定版本并在本地安装。服务不执行包内脚本、不自动升级客户端；权限、审计和版本元数据由后端负责。

## 已确认规则

1. **托管包本体。** 对象存储保存版本化文件；元数据记录可确定下载和安装说明，不只登记外部可变仓库链接。
2. **原子版本输入。** 简单 Skill 可上传单个规范 SKILL.md，复杂 Skill 使用保留目录结构的 ZIP；标准化为不可变包版本。任一校验失败整包拒绝，不产生半成品可分发版本。不提供逐文件增量上传或 Git 拉取。
3. **唯一入口。** ZIP 可以直接以 SKILL.md 为根，或带唯一一层包装目录；剥离后必须有唯一根级 SKILL.md，不递归猜入口。包装外存在其他有效文件、多候选根、非法路径/重复内容等按包校验拒绝。
4. **组织内不可变 Skill Key。** 根 frontmatter 必须有 name/description，name 使用小写 kebab-case，组织内唯一且原地不可改名。新版本 name 必须一致；display_name、文件名和包装目录不是身份，description 可随版本改变。
5. **服务端版本分配。** 版本格式为严格 X.Y.Z；用户明确提供则原样提交，省略时由服务端在原子创建边界分配下一 patch。客户端不能先读最高版本后自行分配。版本由数据库维护，不要求写入 SKILL.md。

## 实施边界

初始版本、显式版本的单调性/重试幂等、审核生命周期、推荐/弃用、上传/维护权限、分发协议、类别授权映射和存储细节尚无完整定稿，不能自行补成既定规范。新增实现须先完成这些决策，并遵守现行组织/业务权限模型，不恢复标签授权。

现有 XLSX 的有界 ZIP 检查可提供实现参考，但不是通用 Skill 包校验器。需要独立包模块、资源限制和恶意归档回归。只在功能实际交付时同步 MCP 契约、launcher 及双归属基础 Skill；现行 employee Skill 不宣称不存在的上传能力。

代码入口：`packages/db/prisma/schema.prisma` 的 SkillEntry、`apps/api/src/skills.ts` 和 `apps/api/src/routes/catalog.ts`。存储能力见 [OSS 适配器](oss-designs.md)。
