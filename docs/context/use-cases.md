# 企业资料中枢当前使用场景

本文仅描述当前公共能力。术语见 [领域模型](../../CONTEXT.md)，具体参数见 [API/MCP 契约](../implementation/api-contract.md)。用户与自己的 agent 对话，agent 通过官方 launcher 使用 SMEDC；服务本身不生成答案或报告。

## 查找制度、手册和经营材料

员工要求查找资料时，agent 发起 evidence search，服务按当前完整业务权限返回相关片段及本页来源链接。agent 根据证据回答并给出处。无相关结果只能说明本次授权范围内未找到，不扩展为企业全部资料不存在。

## 上传并确认处理完成

当前有效 admin 提供原始文件和必要业务属性；employee 无上传权，不能靠提高密级或重登录绕过。Evidence 明确业务类别、整件范围和逐文件密级，照片明确企业及一家门店，结构化资料遵守其数据集字段。

上传被接受后，agent 按返回的 document/import/job ID 轮询成功或安全错误。202/queued 不等于完成；不通过重传、启动 worker 或修改原件替代等待。

## 经营周报或菜品分析

Agent 明确企业、日期和门店范围，查询可读分区覆盖并通过 launcher 下载校验后的 business/dishes CSV，再在本地分析和形成报告。SMEDC 不提供这两个数据集的通用行查询、服务端经营结论或自动周报。

会员、菜品基础目录和供应商目录使用各自独立集团级权限及受控查询；agent 先发现 canonicalName，再按明确条件查询。覆盖和结果仅代表当前获准资料，不等于全企业完整性保证。

## 检疫证明与台账 PDF

管理员按收货单号上传属于一家门店的照片，可先于收货单入库。服务按计划生成/修复每日台账 PDF；上传完成不表示 PDF 就绪。员工查看获准门店/日期覆盖，准备下载包、轮询并领取链接，不触发 PDF 生成，也不能查询原始台账行、汇总或原件。

照片和 PDF 各自授权。员工能读成品 PDF，不代表能单独下载其中照片或供应商资料。照片内容撤下/替换影响成品有效性，单纯照片读取权限变化不改变 PDF 权限。

## 权限配置与拒绝解释

管理员使用企业专属 UI 或获准 MCP 管理入口，查看并维护本企业账号的类别、完整业务范围和密级。普通员工查看本人的实时权限卡。管理员角色不自动赋予普通正文读取权；版本冲突需重新核对配置。

权限不足时可说明具体资料名称和必要概述，但不交付正文、明细或下载能力。共享整件资料要求覆盖全部范围，不能拼接不完整 grant 或用管理员身份绕过读取。

## 入驻和新账号

运维核对企业并开户，用户本人在第一方网页设密码，开发者交付已验证的固定管理入口。新企业先配置、准备、明确激活，再验证业务读取；既有 enabled 企业新增员工沿用企业规则。普通用户不填写 JSON，agent 不接触密码或设置令牌。

## 跨宿主继续工作

每个支持宿主配置官方 stdio launcher。安全存储可用时，同 OS 用户/同服务 origin 共享账号会话；无头内存会话只存在于当前进程。业务资料仍存于服务，所有新请求使用当前服务端权限。

## 管理和清理

已发布检疫证明的归档要求当前有效同组织 admin；未完成上传的有效所有者可取消自身会话。一般员工不能按历史上传者身份归档已发布资料。已签发 URL 保留原 TTL，后续请求和新链接使用当前权限。

真实资料回填、数据库/对象清理、账号/角色/密码操作属于独立运维流程，不属于员工 MCP 使用。发现 Skill 目录只返回元数据；未来技能包托管设计见 [Skills Shop](../implementation/skills-shop.md)，不把它当作现有上传/下载工具。
