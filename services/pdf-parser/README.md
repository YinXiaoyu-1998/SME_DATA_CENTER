# Local PDF parser

`convert_pdf(Path) -> dict` is the qualified local adapter and returns the strict version-one worker DTO. It uses the standard Docling pipeline, Chinese PP-OCRv4 through RapidOCR/ONNX Runtime, and accurate TableFormer. It renders every page for OCR while preserving native text, including PDFs whose visible letters are vector outlines. It never generates image descriptions.

The qualified runtime is Linux with Python 3.12.14 and `uv sync --locked --project services/pdf-parser`. Linux Torch and TorchVision resolve exclusively from the official CPU wheel index; the lock excludes CUDA/NVIDIA/Triton dependencies. The upstream lock resolves different IBM model-library versions on macOS; macOS is suitable for synthetic fixture creation but does not satisfy the exact Linux runtime manifest. Run parser qualification and model-dependent tests in the controlled Linux container. Runtime does not install dependencies or download models.

Before starting the offline runtime, deposit each `model-manifest.json` file at its exact relative path below `SMEDC_PDF_MODELS_PATH` (default: this service's ignored `models/`). The manifest records public source revisions, download URLs, byte lengths, SHA-256 values and licenses. Deployment preparation must verify these artifacts and retain upstream license notices. The adapter verifies all selected files and library versions before initializing models; missing or changed artifacts fail closed. Weights are deliberately absent from source distributions and wheels.

The runtime exposes its manifest-verified Noto CJK font through the system font directory. PDFium uses that font when a PDF references Chinese CID glyphs without embedding them; Docling continues to use the same verified file for OCR rendering.

Run the focused synthetic regression suite with:

```sh
docker build --target qualification --build-context model-cache=/absolute/public-model-cache -t smedc-pdf-qualification services/pdf-parser
docker run --rm --network none --memory=5g --memory-swap=5g --cpus=4 --mount type=bind,src="$PWD/fixtures/evidence/pdf/contracts",dst=/fixtures/evidence/pdf/contracts,readonly smedc-pdf-qualification python -m pytest tests/test_convert.py -q
```

The tests use actual native, raster and vector-outline PDFs and deny socket connections. They cover table cell pairs, physical pages, mixed-page OCR, valid repeated rows, mixed content in one ruled cell, model failures, malformed PDFs, oversized rendering and page limits. They require the prepared model directory.

For complete native straight-line grids on unrotated pages with a zero-origin, unclipped canvas, cell boundaries come from the original PDF. Rotated, translated or cropped canvases retain TableFormer because original native geometry and displayed geometry differ. Missing boundaries permit only rectangular merged cells. When TableFormer returns an invalid structure and the straight ruling detector cannot recover a grid, a second path can use original filled rectangles only if they form a complete, non-overlapping rectangular tiling. Its envelope must cover all four predicted ROI boundaries within the explicit 3 PDF point tolerance; nonempty native glyph centers inside that ROI but outside the recovered envelope reject recovery, so prediction-error margins cannot hide additional content. It retains the same rotation/crop guards and accepts only direct page objects with axis-aligned closed rectangle paths. Valid model structures keep the existing path. Incomplete/overlapping fills, irregular grids, raster grids and unruled tables fail closed if the model structure is invalid. OCR that crosses multiple ruled cells is recognized again from individual cell crops. Native glyph bounds and normalized text comparisons remove overlapping duplicate OCR while retaining separate bitmap/outline text. There is no document-wide text deduplication.

The manifest declares finite input, page, rendering, output, time, memory and concurrency budgets. Rendered-pixel preflight counts the largest intermediate raster: the pinned backend oversamples the 3x OCR image by 1.5x, yielding scale 4.5, with each dimension rounded up as PDFium does. The adapter enforces input/pages/render/output/table-work limits and configures the Docling timeout. The service adds authenticated bounded uploads, one job at a time, a hard conversion deadline, and process-group termination on timeout or disconnect. Runtime startup requires a finite Linux cgroup v2 memory ceiling of at most 8 GiB; container configuration must deny egress. In isolated Linux/arm64 containers with a 5 GiB cgroup ceiling, the selected 4- and 19-page originals completed parsing and indexing; the parser container's cumulative `memory.peak` reached 1.82 and 1.99 billion bytes after those samples. The 8 GiB parser ceiling and 12 GiB host recommendation remain provisional deployment budgets pending Linux/amd64 qualification with the other services. The 104-page original parsed locally but its unbatched Qdrant upsert returned HTTP 400, so its complete ingestion is not qualified. `RLIMIT_AS` limits virtual address space rather than measured RSS.

The manifest fingerprint identifies selected artifacts and parameters. Bump `adapterVersion` when changing parsing behavior after this initial qualification. Private real-sample questions, source hashes, corrections, parser outputs and measurements remain outside the tracked service.

The internal service accepts only `POST /v1/parse`, `Content-Type: application/pdf`, and raw PDF bytes, with `Authorization: Bearer <SMEDC_PDF_SERVICE_TOKEN>` (at least 32 bytes). It rejects query parameters, content encoding, paths and URLs. `GET /health` is the only unauthenticated endpoint and returns only a liveness status. `GET /v1/ready` requires the same Bearer token and returns `{status: "ready", schemaVersion: 1, parserFingerprint}` only after startup validation of all manifest model hashes and critical runtime package versions. Missing/corrupt models or a mismatched runtime return safe 503 errors; a wrong token returns 401. Downstream workers and PDF upload gates must call this readiness endpoint rather than liveness. The startup check runs in a thread, uses no OCR, and caches the result for immutable read-only deployment assets. Restart after repairing/changing models or runtime packages; requests do not rescan assets and failed readiness remains closed until restart. Parsing also rejects requests while cached readiness is unsuccessful. Responses use the shared `PdfEvidenceResult`; failures contain only safe `code` and `message`. Busy requests receive 503 with `Retry-After: 5`; there is no conversion queue.

Capacity is acquired before body reception and held until the private request directory and disposable subprocess group are cleaned up. Input is streamed in 64 KiB chunks, capped at 50 MiB and a 120-second total upload deadline. The subprocess has a 3600-second hard wall-clock deadline; stdout is capped while being read at 16 MiB. Each child has a CPU-time limit, 128 file descriptors, a file-size limit, and disabled core dumps. RSS/page-cache memory is limited by the container cgroup, not `RLIMIT_AS`. Request directories use random names and mode 0700; no route serves files. Configure the HTTP server with handler cancellation enabled (the shipped entrypoint does this); dropping the caller connection kills the process group before releasing capacity.

Build from this service directory only:

```sh
docker build -t smedc-pdf-parser:local services/pdf-parser
```

`.dockerignore` is an allowlist, excluding credentials, private PDFs/results, virtual environments, model caches and process reports. The build runs `uv sync --locked --no-dev --no-editable` on Python 3.12.14/Debian bookworm and prepares only SHA-256/size-verified manifest files and license notices. Optional `--build-context model-cache=/path/to/public-model-cache` can supply those exact public files (including manifest notices); other files in that cache are never copied into the final image. The fallback fetch happens only during image construction. The runtime retains model attribution, upstream notices and package wheel licenses, has no package installer or download step, runs as UID/GID 10001, and treats missing/corrupt models as safe failures.

Run on a private network with no external route, never a public ingress. For an offline verification use `--network none` and send requests through container loopback with `docker exec`. The required runtime controls are `--read-only --tmpfs /tmp:rw,noexec,nosuid,size=128m,mode=1777 --memory=8g --memory-swap=8g --cpus=4 --pids-limit=128 --cap-drop=ALL --security-opt=no-new-privileges`; provide the service token via deployment secret/environment injection. These are container controls, not Dockerfile directives; deployment integration belongs to the runtime release task. Local Linux/arm64 short-document qualification used a 5 GiB parser ceiling and does not qualify the 104-page end-to-end workload or production CPU architecture.

Run the complete service package tests after preparing models:

```sh
docker run --rm --network none --memory=5g --memory-swap=5g --cpus=4 --mount type=bind,src="$PWD/fixtures/evidence/pdf/contracts",dst=/fixtures/evidence/pdf/contracts,readonly smedc-pdf-qualification python -m pytest tests -q
```

The protocol tests consume the same synthetic JSON fixtures as the Node domain validator and enforce matching per-table/cumulative budgets, including UTF-16 expansion for non-BMP text. Service tests use real HTTP connections; runner tests use real child processes and descendants, including cancellation during process startup. Native filled-grid regressions prove adjacent merged regions retain both distinct texts and reject overlapping/rotated geometry. The existing synthetic extraction tests continue to exercise actual OCR/native text/tables/picture regions without image descriptions.

The `qualification` build target includes only synthetic Python tests and pinned development dependencies. It is separate from the final non-root runtime target; no private PDF enters either build context. Refresh Debian security packages during release builds (invalidate the runtime apt layer) and scan OS plus Python libraries using the repository policy. CPython patch updates are also explicit because library scanners do not cover every interpreter issue.
